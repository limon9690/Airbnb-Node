# HotelService

Owns hotels and room inventory, and generates room availability in the background instead of having it pre-seeded.

## What it does

- Hotel CRUD
- Room inventory: one row per room category per calendar day, generated by a BullMQ job rather than sitting pre-seeded in the database
- A cron-driven scheduler keeps extending that availability further into the future on its own
- Serves availability lookups and room-claim requests for BookingService

## Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | /api/v1/hotels/health | none | health check |
| GET | /api/v1/hotels | none | list hotels |
| GET | /api/v1/hotels/:id | none | get a hotel |
| POST | /api/v1/hotels | OWNER / ADMIN | create a hotel |
| PUT | /api/v1/hotels/:id | OWNER / ADMIN | update a hotel |
| DELETE | /api/v1/hotels/:id | OWNER / ADMIN | delete a hotel |
| POST | /api/v1/hotels/generate-rooms | OWNER / ADMIN | queue room generation for a category and date range |
| GET | /api/v1/rooms/available-rooms | none | find unbooked rooms for a category and date range |
| PUT | /api/v1/rooms/update-booking-id | internal API key | claim rooms for a booking |
| PUT | /api/v1/rooms/release-booking-rooms | internal API key | release rooms tied to a booking |
| POST | /api/v1/scheduler/start | ADMIN | start the availability scheduler |
| POST | /api/v1/scheduler/stop | ADMIN | stop it |
| GET | /api/v1/scheduler/status | ADMIN | check whether it's running |
| POST | /api/v1/scheduler/extend | ADMIN | trigger one extension run manually |

The `/api/v1/rooms` write endpoints aren't for users — they exist for BookingService to call directly, and are protected by a shared internal API key instead of a JWT.

## Environment variables

See `.env.example`. `ACCESS_TOKEN_SECRET` has to match AuthService and BookingService; `INTERNAL_API_KEY` has to match BookingService.

## Running locally

```bash
cp .env.example .env
npm install
npx prisma migrate dev
npm run dev
```

Runs on port 3000 by default. Needs Redis for the room-generation queue and scheduler.

## Depends on

Redis, for the BullMQ room-generation queue.
